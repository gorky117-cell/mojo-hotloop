## Methodology

### What Is Measured

Each benchmark measures **end-to-end wall-clock time** of a single decorated
function call, from Python call-site to result return, including:

- FFI boundary overhead (Python → Mojo → Python)
- Native computation time
- Result boxing (Mojo → PythonObject)

It does **not** measure: JIT compilation time, shared-library loading time
(one-time cost at import), or garbage collection.

### Timing

```python
import time

times = []
for _ in range(100):   # 100 trials per benchmark
    t0 = time.perf_counter()
    result = fn(*args)
    t1 = time.perf_counter()
    times.append(t1 - t0)

times.sort()
p50 = times[len(times) // 2]           # median (reported)
p5  = times[len(times) // 20]          # 5th percentile (best-case)
p95 = times[len(times) * 19 // 20]    # 95th percentile (worst-case)
```

The **p50 (median)** is reported as the headline speedup. This is more
representative than the minimum, as it captures steady-state performance
including OS scheduler jitter on a typical developer machine.

### Comparison Baselines

| Baseline | Description |
|----------|-------------|
| **CPython 3.12** | The undecorated Python function in the same process |
| **Numba (JIT)** | `@numba.jit(nopython=True)` on a compatible equivalent |
| **Regex** | `re`-compiled pattern on the same workload |
| **RapidFuzz** | C-accelerated Levenshtein library |
| **NumPy** | Vectorized NumPy on equivalent arrays |

### Source Distinction

> [!IMPORTANT]
> **AST-auto** = code generated by the deterministic AST transpiler from the
> unmodified Python source, with no manual Mojo editing.
>
> **Handwritten** = manually authored Mojo code (not part of the
> `mojo-hotloop` automated pipeline).
>
> All results in this document are **AST-auto** unless explicitly noted otherwise.

## Results — 7 Real-World Use Cases

All benchmarks run with `--engine=ast` (deterministic, offline transpilation, compiled with `mojo build --emit shared-lib -O3`). Both `@hotloop` (full Python wrapper + dispatch) and Direct Mojo module calls are shown alongside the best semantically equivalent baseline (`Numba`, `NumPy`, `Compiled Regex`, `RapidFuzz`).

### 1. Quantitative Backtest (100,000 ticks)

**Function**: `stateful_trailing_backtest(ticks, start_price, stop_pct, fee_rate)` (`examples/quant_backtest/bench.py`, 100 iterations)  
**Engine**: AST-auto

| Implementation | p50 (ms) | p95 (ms) | Mean (ms) | Speedup vs Python (p50) |
|----------------|----------|----------|-----------|-------------------------|
| Python 3.12    | 43.780   | 62.290   | 46.258    | 1.00x (baseline) |
| Numba `@njit` (warmed; 1810.4 ms JIT) | 0.604 | 0.828 | 0.637 | 72.48x |
| **Mojo `@hotloop` (AST)** | **0.531** | **0.764** | **0.570** | **82.39x** (1.14x vs Numba) |

This stateful loop with tight conditional branches and float arithmetic has no data-parallel array structure, allowing native Mojo AOT code to run slightly faster than warmed Numba without JIT startup latency.

## Reproducing Benchmarks

```bash
# Clone and set up
git clone https://github.com/mojo-hotloop/mojo-hotloop
cd mojo-hotloop
python3 -m venv .venv
.venv/bin/pip install -e .

# Build all use cases
.venv/bin/python audit/test_ast_provenance.py

# Run verification suites
.venv/bin/python audit/run_all_verifications.py

# Example: run quant_backtest benchmark
.venv/bin/python -c "
import time, sys
sys.path.insert(0, '.')
from examples.quant_backtest.original import stateful_trailing_backtest

times = sorted(
    time.perf_counter() - (t := time.perf_counter()) or t - t + (time.perf_counter() - t)
    for _ in range(100)
    if not setattr(stateful_trailing_backtest, '_t', None)
)
# Proper timing:
times = []
for _ in range(100):
    t0 = time.perf_counter()
    r = stateful_trailing_backtest(100000, 100.0, 0.05, 0.001)
    times.append(time.perf_counter() - t0)
times.sort()
print(f'p50: {times[50]*1000:.3f} ms, backend: {stateful_trailing_backtest._last_backend}')
"
```

## Limitations and Caveats

1. **WSL2 overhead**: Benchmarks run inside WSL2 on Windows. Linux-native performance
   may differ slightly (typically ±5–10% for CPU-bound workloads).
2. **Single-threaded**: All measurements are single-threaded. The `@hotloop`
   decorator does not automatically parallelize.
3. **Compiler flags**: AST-generated Mojo modules are compiled with `mojo build --emit shared-lib -O3`; the transpiler relies on LLVM `-O3` optimizations rather than emitting manual SIMD intrinsics. The speedups come from native compilation, zero-copy `ndarray` pointer dispatch, and `_PyStr` ASCII/codepoint optimizations.
4. **Cold start**: `.so` loading at import time is not benchmarked. It is a
   one-time cost (typically 5–50 ms depending on disk speed).
5. **Numba comparison**: Numba warm-up time is not included in the Numba p50
   values shown above.
